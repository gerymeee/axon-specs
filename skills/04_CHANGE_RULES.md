# 04 - Change Rules

**Purpose:** Review both sides of a contract before changing any field, rule, or state transition.
**Confidence note:** Verified against the Axon working-tree documentation baseline on 2026-11-23. Application code was unavailable. The code wins (see [16](16_ENGINEERING_PRINCIPLES.md)).

The [database choices](../db-design-choices.md) describe these lockstep sets using example schemas. The [business logic](../business-logic-v1.0.md) supplies the draft access requirements. Here the paths name sources and affected repositories, since there are no implementation paths yet.

| # | Lockstep set and paths | Miss → what happens | Retest |
|---|---|---|---|
| 1 | **Identity and payload.** `axon-specs/db-design-choices.md` §§1–3. Client store and mapper, API upsert and serializer, Postgres schema. Keep `uuid`, relationship `*_uuid` columns, and matching names in sync. Exclude both stores’ `id` and the client’s `synchronized_at` from exchange. | Distinct records collide if the mapper treats local integers as shared identity. | Create related records offline on two stores, push twice, then pull and verify UUID joins. |
| 2 | **Dirty state and conflicts.** `axon-specs/db-design-choices.md` §6. Local mutation code bumps `updated_at`. Push selection compares it to `synchronized_at`. Push acknowledgement and pull update the sync marker. API/Postgres merge uses the same ordering and tie rule. | A missing stamp silently skips a local edit. An acknowledgement for an earlier snapshot can mark a later edit clean (06 #1, #4). | Test a dirty pull, exact-version acknowledgement, in-flight local edit, stale write, empty change stamp, and timestamp tie. |
| 3 | **Soft deletes.** `axon-specs/db-design-choices.md` §§5–6. Delete writers, ordinary reads and aggregates, scoped pull, and any live-only unique index must agree on `archived_at`. | A row vanishes locally but stays visible on peers if pull filters the tombstone. Archival without a change stamp can leave it unsent. | Archive a row and pull on a second client. Re-create an archived link with the same natural key. Verify aggregates. |
| 4 | **Ownership, scope, and attribution.** `axon-specs/db-design-choices.md` §§3–4 and `axon-specs/business-logic-v1.0.md`. Keep push allowlists, session-derived `created_by` and action actor columns, scoped pull, and client access views aligned. | If API authorization diverges from scoped reads, clients may receive or modify records outside their permissions. | Use two fictional accounts with different roles and confirm server-stamped actors plus category-appropriate read and write access. |
| 5 | **Schema, enums, and projections.** `axon-specs/db-design-choices.md` §§7–9. Update Postgres migration and SQLite migration, push allowlist and pull mapping, enum validation and UI. Preserve snapshot semantics for duplicated fields. | One store can reject values the other accepts. Old payload nulls can silently undo backfills. | Fresh schema, existing data, legacy payload, each enum value, and a new column across a version mix. |
| 6 | **Parent and link integrity.** `axon-specs/db-design-choices.md` §§3, 7–8. Sync, parent lookups, retry behavior, and link uniqueness share the same `*_uuid` semantics. `note_tag` uses `(note_uuid, tag_uuid)` in the example. | If a skipped child is treated as fully consumed, its parent may arrive later and the child stays absent. | Pull child first, then parent. Verify retry restores the child and natural-key adoption preserves one live link. |
| 7 | **Candidate identity.** `axon-specs/git-guidelines.md`, Part 2. Match the tested bundle, its `release` commit, and its exact candidate tag. | A substituted build invalidates the evidence that was used for production approval. | Match tag target and published artifact before every promotion (see 10). |

Highest-risk changes affect dirty acknowledgement, tombstones, actor attribution, or schema compatibility. Review the entire affected row in this table before changing one participant.
